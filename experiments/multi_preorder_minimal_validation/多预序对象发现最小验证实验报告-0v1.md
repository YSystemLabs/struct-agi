## 1. 文档定位

本报告对应 [多预序对象发现最小验证实验](./多预序对象发现最小验证实验.md) 的 v0.9 canonical rerun，服务于两个目的：

1. 给出一份可读的叙述性结果总结，而不是只保留机器可读的 JSON 产物；
2. 明确这条路线在当前仓库中的冻结定位：它是一个 **探索性最小验证基线**，而不是主理论的正式 Phase A 验证包。

因此，本报告不宣称“多预序路线已经完成主理论验证”，只回答一个更弱的问题：

> 在固定任务池、固定模板池、固定搜索边界下，多预序对象发现是否表现出值得保留的局部下游效用与结构稳定性信号？

## 2. 实验目标与范围

本轮实验的目标不是开放式规则发明，也不是完整任务解释后验闭合，而是检验多预序对象发现作为前语义结构层，是否能在一个严格受限的设置中优于常见对象化/分割基线。

范围固定如下：

* 数据集：ARC-AGI-2 `training` split；
* 任务池：附表 A 的 16 个主任务；
* 验证协议：task-internal leave-one-train-pair-out，共 61 个 task-fold；
* 方法比较：`multi_preorder`、`cc4`、`cc8`、`bbox`、`raw_local_feature_clustering`；
* 模板池：固定为 `identity / translate / recolor / delete / crop_selected_bbox`；
* 结果定位：探索性最小验证，不上升为主理论正式通过结论。

附表 A 的主任务组成是：

* `translate`：6 个；
* `recolor`：1 个；
* `crop_selected_bbox`：9 个。

## 4. 关键结果

### 4.1 方法汇总

| 方法 | exact tasks | mean pixel accuracy | mean top1 train J | robustness |
| --- | ---: | ---: | ---: | ---: |
| multi_preorder | 4 | 0.589007 | 1.418162 | 0.656250 |
| cc4 | 3 | 0.591242 | 1.261674 | 0.570513 |
| cc8 | 3 | 0.541656 | 1.371664 | 0.576389 |
| bbox | 2 | 0.539053 | 1.283711 | 0.555556 |
| raw_local_feature_clustering | 4 | 0.589007 | 1.361912 | 0.604167 |

从这张表可以看出：

1. `multi_preorder` 在 exact task 数上优于 `bbox / cc4 / cc8`，但与 `raw_local_feature_clustering` 持平；
2. `multi_preorder` 的 `robust_equivalence_rate` 最高，说明其结构签名在扰动下更稳定；
3. `multi_preorder` 的 `mean_top1_train_j_score` 最差，说明在当前显式复杂度计入方式下，它没有体现出共享压缩收益；
4. `cc4` 的汇总 `mean pixel accuracy` 略高于 `multi_preorder`，因此如果只看简单任务均值，`multi_preorder` 并没有形成无争议优势。

### 4.2 配对比较结果

对全部 61 个 task-fold，`multi_preorder` 与各基线的配对结果为：

| 基线 | paired exact win rate | paired mean pixel gain |
| --- | ---: | ---: |
| bbox | 0.557377 | 0.044802 |
| cc4 | 0.516393 | -0.011691 |
| cc8 | 0.516393 | 0.040334 |
| raw_local_feature_clustering | 0.500000 | 0.000000 |

这说明：

* `multi_preorder` 在 formal 主终点定义下，确实对至少一半的基线达到了 `W_em >= 0.5`；
* 但它并没有对所有强基线都取得一致优势，尤其对 `cc4` 的像素精度平均增益为负，对 `raw_local_feature_clustering` 只有平局；
* 因而更合理的解读是“存在值得保留的局部效用”，而不是“已经形成稳定压倒性优势”。

## 5. Formal Verdict

本次 canonical rerun 的 formal verdict 是：

```text
primary-supported-secondary-failed
```

三个判据的结果如下：

1. **Criterion 1: paired exact win rate**
   通过。`multi_preorder` 对 `bbox / cc4 / cc8 / raw_local_feature_clustering` 的 paired exact win rate 分别为 0.557377、0.516393、0.516393、0.500000，满足“至少一半基线达到 0.5 以上”的要求。

2. **Criterion 2: mean accuracy gain**
   通过。对所有基线的 paired mean pixel accuracy gain 简单平均后为 0.018361，大于 0。

3. **Criterion 3: secondary endpoints**
   未通过。`multi_preorder` 的 robustness 明显优于基线平均值（0.656250 vs 0.576656），但 shared compression 更差（1.418162 vs 1.319741；lower is better）。因此它没有同时满足“一个严格更好、另一个不差”的辅终点要求。

这个 verdict 的含义不是“路线完全失败”，而是：

> 多预序路线在固定模板池下表现出局部下游效用与更强扰动稳定性，但当前还不能说它已经带来了与主理论相一致的共享压缩收益。

## 6. 结果解释

### 6.1 可以保留的信号

当前结果至少支持以下较弱判断：

1. 多预序结构候选不是纯噪声。它在 exact win rate 和 fold-level mean accuracy gain 上对若干基线取得了正结果。
2. 多预序结构签名具有更强的扰动稳定性。`robust_equivalence_rate = 0.65625` 是所有方法中最高的。
3. 这条路线适合作为后续自动对象发现路线的 **强结构偏置对照基线** 保留。

### 6.2 不能做出的结论

当前结果不能支持以下更强说法：

1. 不能说多预序路线已经通过主理论的正式最小验证；
2. 不能说多预序路线在整体任务性能上稳定优于所有简单基线；
3. 不能说多预序路线已经体现出更优的共享压缩或更低的训练解释复杂度；
4. 不能把这份探索性包上升解释为主理论 Phase A 的正式实验包。

特别要注意的一点是：`multi_preorder` 的 exact task 数虽优于 `cc4 / cc8 / bbox`，但与 `raw_local_feature_clustering` 持平；同时 `cc4` 的 mean pixel accuracy 还略高于它。这些事实都要求对结果口径保持克制。

## 7. 冻结决定

基于以上结果，当前冻结决定如下：

1. 将本实验包冻结为 **探索性基线包**，而不是正式理论验证包；
2. 将 `multi_preorder` 在当前实现和当前 canonical report 下冻结为后续文档中的 `multi_preorder_v0_baseline`；
3. 后续 SoftWTA / SoftHebb 或其他自动对象发现路线，可以拿这个冻结基线作比较，但不应把它当作主理论已被验证的证据；
4. 若未来要调整任务池、模板池、J_train 定义、扰动协议、或本地实现边界，应提升版本号，而不是继续沿用 `v0.9` 名称。

换句话说，这次冻结保留的是：

> 一份可复现、可比较、口径收敛的 exploratory baseline。

而不是：

> 一份已经证明多预序对象发现路线成立的正式理论实验包。

## 9. 最终结论

**本轮实验不通过 formal threshold，但通过“探索性基线冻结”门槛。**

最终结论可以压缩成一句话：

> 多预序对象发现路线在当前最小设置下表现出一定下游效用和更强鲁棒性，因此值得作为冻结基线保留；但由于 shared compression 未获支持，它尚不足以构成主理论的正式验证证据。
